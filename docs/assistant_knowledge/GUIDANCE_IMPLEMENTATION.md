## 玩家使用流程

1. 重启本地后端，重新进入 Unity Play 模式，完成当前强制教程。
2. H 唤醒小助手→问点什么。远处询问“我想学数值孔径，在哪里？”仍可获得位置标记。
3. 靠近后点击新增的“下一步”，再点击发送。助手按当前状态给出一个操作及观察目标。
4. 关闭问答窗口，按说明自己操作。屏幕保留操作提示卡；可点击 × 关闭。状态变化或 120 秒超时后提示卡清除，不会自动再调用 API。
5. 操作后再次询问下一步，或点击“如何退出”再发送。问答期间实验输入仍由原有输入保护阻止，避免打字意外操作仪器。

“下一步/如何退出”只是填入问题，点击发送才请求。每次真实问答仍包含生成与语义复核两次模型调用。随机问候、闲置提醒、状态采集、卡片刷新和高亮均在本地运行。

## 38 个动作的覆盖范围

动作事实共用 `Assets/Resources/AssistantGuidanceActions.json`，Unity Resources 与 Python 后端读取同一份文件，含动作 ID、关联交互、知识主题、桌面/XR 操作及观察目标。不要分别修改两套文案。

| 流程 | 本次启用的说明 | 主要状态依据 |
|---|---|---|
| 显微镜拆解 | 预装配、展开、逐层退出、选择/退出部件 | 原模式控制器、装配动画、选择控制器、距离 |
| NA | 从已选上部光学组件启动、滑块调节、退出 | 当前实验绑定、可用按钮/滑块、转场、CurrentNA |
| 空间频率 | 从已选物镜启动、High/Middle/Low、两种照明、退出 | 当前绑定、Toggle/Button 实际可用性、频率档位和照明 |
| SNOM 准备 | 入口面板、Begin Operation、三种探针、安装、启动、更换探针 | 实际交互范围、WorkflowPhase、选中/安装索引、可见控件 |
| SNOM 演示 | 上一/下一段、播放/暂停、重播、部件模式、退出 | 当前讲解阶段、部件模式、播放状态、有效阶段边界 |
| 显微观察 | 拾取、放置、推进观察视点、取下、照明开关/调节、物镜切换、粗细调焦、退出 | 当前注册显微镜、实际手持对象、载物台对象、观察相机、输入配置 |

约束经过实际源码复核：调焦函数只在观察相机激活时有效；SNOM 安装期间不能再安装或启动；Next/Previous 不跨越首末项；Change Probe 只在准备完成且按钮可用时建议。手持状态依据实际对象层级，不把原有“曾经拿过样本”的布尔值当成当前手持证据。

鼠标/键盘操作会核对 `CameraTryMove` 当前配置是否与共享文案一致；若按键已自定义，则暂不提供对应固定键位说明，避免提示错误按键。UI 按钮说明不依赖这些快捷键。XR 使用设备检测选择手柄/射线文案，物理设备的实际表现仍需头显验收。

条件不成立的传送、载物台平移、可选教程入口，以及未实现的共聚焦针孔/Z-stack 不会作为可执行步骤。强制教程按原流程进行，助手不提供绕过教程的按键。

## 数据与输出约束

每次发送新增 `guidance`：快照 ID、共享目录版本、desktop/xr、当前模式、阻塞状态、样本状态、观察视点；以及相关模块的 NA、频率、照明、SNOM 阶段等字段和 `allowedActionIds`。后端只把当前模块有效字段提供给模型，不把其他模块的默认值说成观测值。

后端验证字段、数值、动作 ID 和阶段关系，构建 `GUIDANCE_CONTEXT.allowed_actions`。DeepSeek 选择一个当前动作或一个导航目标；一次不得混合 `learn:` 和 `highlight:`。原理问题继续解释，范围外仍固定拒答。

操作回复示例：

```json
{"kind":"guide","answer":"拖动 NA 滑块，比较光锥变化。","interaction_ids":["na_experiment"],"suggested_action_ids":["learn:na_adjust"],"knowledge_topics":["numerical_aperture"]}
```

模型 answer 不直接成为可执行说明。后端将其替换为共享目录的准确操作与观察文本，再审核所选动作是否符合用户问题或其必要前置步骤。无关请求即使选择了合法动作也不能通过语义复核。客户端同样按共享目录呈现，不执行模型给出的任意文本、按钮事件或实验方法。

响应另带 `guidanceSnapshotId`。收到回复时，Unity 重新读取当前状态；如果切换模式、改变实验值、换部件、完成安装、按钮变为不可用等导致快照不同，则显示“实验状态已经变化，请重新询问”。旧回复不直接作用到新实验。状态改变只表示程序变化，不表示学习完成。
