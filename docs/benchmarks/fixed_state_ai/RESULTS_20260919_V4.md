## Validity boundaries

The v3 run `20260919_072840_b25eb8bcbc2c4ac39f7ad8b69e017742` exposed four supported non-guide candidates that contained direct operating instructions and were consequently converted to refusal. It informed the v4 prompt and repair change. The two single-case runs at 08:07 then preceded this full rerun. Therefore these are development/regression results on a reused suite, not held-out evaluation. Do not treat the v3/v4 runs as a controlled ablation or infer causal gains from their difference.

No rejection or repair occurred in this final run. It therefore does not measure rejection sensitivity or recovery success under injected failures. Same-model semantic review is an internal gate, not an independent rating of factual correctness. The observed 100% values are finite-fixture conformance rates; do not report universal accuracy, 100% unsupported-request handling under full human rubrics, or an independent final task-success score.

All records set `client_apply_executed=false`. ST01–ST10 and PC01–PC02 are separate specifications, not completed outcomes in these files. Live reminder display, marker rendering, state changes and stale-response rejection remain unevaluated by this run. There is no state-ablated baseline, held-out query set, speech benchmark or learning-gain comparison here. The 78 calls repeat only 26 cases and should not be presented as 78 independently sampled scenarios.
